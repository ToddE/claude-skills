# Clean Style Rules

Apply whenever producing external-facing prose: documents, emails, decks, customer-facing
copy, or any writing meant for people outside internal technical work.

- No em-dashes, hyperbole, or extra words.
- Direct and concise; humble in customer-facing docs.
- No metaphors like "trap" or "tax."
- No contrastive constructions ("not X, it's Y") — state the point directly.
- No dramatic transitions, filler phrases, or restating the same point twice.
- Define jargon or skip it.
- Active voice only — no passive constructions, no inanimate subjects performing human
  actions (e.g. "the complaint becomes a fix").
- No sentences starting with a Wh- word (What, Why, How, etc.).
- No sentences starting with a broad quantifier (Every, All, Each) as a formulaic setup.
  Name the specific subject instead: not "Every skill here is a template," but "These
  skills follow a fixed template" or, often, cut the sentence entirely.
- Vary sentence length and paragraph endings — don't let three sentences in a row match
  rhythm; two items beat three.
- Name the specific thing instead of vague declaratives ("the implications are
  significant") or lazy extremes ("always," "never").
- Don't use "real" as a throwaway intensifier ("a real limitation," "a real cost"). If it
  adds nothing, cut it. If you need to distinguish something from a hypothetical or
  superficial version, name that distinction directly instead of leaning on "real."
- Write to the reader directly ("you," not "people"); skip narrator-from-a-distance
  framing.
- Cut lines that sound like pull-quotes.
- State facts plainly — skip softening, over-justifying, hand-holding.

## Applying this as a rule instead of a skill

This checklist works as a triggered skill (see `../SKILL.md`) or as an always-on rule. If
you want it to apply to everything you write without needing to trigger it, save this file
(or its contents) as `~/.claude/rules/writing-style.md` for every session on your machine,
or paste it into a project's `CLAUDE.md` to scope it to one project. See this repo's
top-level README ("How to Use These Skills," Option 3) for the distinction between
installing something as a skill versus a rule.
