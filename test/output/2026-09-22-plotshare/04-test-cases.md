# Test Cases: Claim a Surplus Listing

| Test Case ID | Title | Covers | Preconditions | Steps | Expected Result |
| --- | --- | --- | --- | --- | --- |
| TC-ClaimSurplusListing-01 | Successful claim | Basic Path | Garden is onboarded. A surplus listing exists and is within its claim window. Member is a registered member of the same garden. | 1. Browse the surplus board and find the listing. 2. Select "Claim." 3. Observe the app's response. | The listing is marked claimed by Member, removed from the surplus board, and Other Member has been notified. |
| TC-ClaimSurplusListing-02 | Two members claim the same listing at nearly the same time | Alternate Path A | Same as TC-01, plus a second member's claim is processed moments before Member's. | 1. Select "Claim" on a listing another member just claimed. 2. Observe the app's response. | Member is returned to browsing the surplus board (rejoin at Basic Path #1); the listing remains claimed by whichever member's claim was processed first, and Member's attempt is not recorded. Not a use case Post-Condition, since this path rejoins rather than terminates; this is state at the point of rejoin. |
| TC-ClaimSurplusListing-03 | Claim window has expired | Exception Path A | Same as TC-01, except the listing's claim window has already expired. | 1. Select "Claim" on an expired listing. 2. Observe the app's response. | Member is returned to browsing the surplus board (rejoin at Basic Path #1); the expired listing remains unavailable to Member and flagged for food bank routing. Not a use case Post-Condition, since this path rejoins rather than terminates; this is state at the point of rejoin. |
