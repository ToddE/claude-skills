# Writing Rules

Apply these to the prose parts of a use case: the one-sentence description, Candidate
Summaries, Actor roles, path actions, Post-Condition(s), and Open Issues/Notes. The table
structure and fixed phrases ("END OF USE CASE," "Use case continues at Basic Path #N.") are
unaffected.

- No em-dashes, hyperbole, or extra words.
- Active voice. The actor does the action: "Platform sends the webhook," not "The webhook is
  sent."
- One action per step. If a step needs "and then," it is two steps.
- No filler or restating the same point twice.
- No contrastive constructions ("not X, it's Y"). State the point directly.
- No metaphors. Name the specific thing, record, or system value.
- Define jargon the first time it appears, or skip it.
- Name the specific subject instead of vague words like "it," "the system," or "the data"
  when more than one could apply.
