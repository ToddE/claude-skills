# Test Cases: Draft a Full Use Case

| Test Case ID | Title | Covers | Preconditions | Steps | Expected Result |
| --- | --- | --- | --- | --- | --- |
| TC-DraftFullUseCase-01 | Successful full draft | Basic Path | A candidate is confirmed via Use Case Discovery, or the flow is described directly. Target document's existing actor names are known. | 1. Confirm the candidate exists (or provide the flow directly). 2. Provide the Basic Path when asked. 3. Provide known Alternate/Exception paths when asked. 4. Receive the completed use case. | A complete use case document exists in the fixed format: Assumptions, Actors, Trigger(s) if applicable, Basic Path, Alternate Paths, Exception Paths, Post-Condition(s), and Open Issues/Notes, in that order. Its Post-Condition(s) are phrased as checkable states, not a narrative recap. |
| TC-DraftFullUseCase-02 | User doesn't know alternate or exception paths yet | Alternate Path A | Same as TC-01, through the point Claude asks whether any alternate or exception branches are already known (Basic Path #5). | 1. Say no alternate or exception paths are known yet. 2. Observe Claude's handling of the Exception Paths section. | The Exception Paths section contains `TBD` rather than an invented or skipped section, at the point the use case continues at Basic Path #7. (Rejoin-point state, not the eventual Basic Path outcome, per this skill's own rule for non-terminal paths.) |
| TC-DraftFullUseCase-03 | Self-check catches and fixes a violation | Exception Path A | A draft use case exists and is being self-checked (Basic Path #8). | 1. Self-check finds a violation (e.g. a missing actor, a duplicate consecutive step, a missing Post-Condition). 2. Observe how Claude handles the draft. | The draft no longer contains the violation found during self-check, at the point the use case continues at Basic Path #8. (Rejoin-point state; the user is never shown the violating draft.) |
