# Functional Requirements: Draft a Full Use Case

| Requirement ID | Requirement | Component | Detail | Acceptance Criteria | Priority | Source |
| --- | --- | --- | --- | --- | --- | --- |
| REQ-DraftFullUseCase-01 | Claude shall reuse a confirmed candidate's Name, Summary, and Actors from Use Case Discovery when one exists, instead of re-deriving them. | Claude | Basic Path steps 1-2. | When a confirmed candidate exists, Claude does not re-ask for a Title, Summary, or Actors already provided by Use Case Discovery. | TBD, pending user input | Basic Path #1-2 |
| REQ-DraftFullUseCase-02 | Claude shall gather the Basic Path and known Alternate/Exception paths from the user conversationally before drafting. | Claude | Basic Path steps 3-6. | The use case is not drafted until the user has provided the Basic Path sequence and been asked about known variations. | TBD, pending user input | Basic Path #3-6 |
| REQ-DraftFullUseCase-03 | Claude shall draft the use case following the exact section order and Basic Path table rules defined by the format spec. | Claude | Basic Path step 7. | The drafted document's sections appear in the fixed order (Assumptions, Actors, Trigger(s) if applicable, Basic Path, Alternate Paths, Exception Paths, Post-Condition(s), Open Issues/Notes), with no invented or renamed sections. | TBD, pending user input | Basic Path #7, Post-Condition (fixed format) |
| REQ-DraftFullUseCase-04 | Claude shall self-check the draft against the format spec before presenting it, and fix any violation found rather than presenting it uncorrected. | Claude | Basic Path step 8; Exception Path A. | No use case is shown to the user with a known self-check violation still present. | TBD, pending user input | Basic Path #8, Exception Path A |
| REQ-DraftFullUseCase-05 | Claude shall write `TBD` under Exception Paths when the user doesn't know any alternate or exception paths yet, instead of guessing or omitting the section. | Claude | Alternate Path A. | The Exception Paths section is never blank or missing when the user has been asked and doesn't know; it contains `TBD`. | TBD, pending user input | Alternate Path A |
| REQ-DraftFullUseCase-06 | Claude shall phrase every Post-Condition as a checkable state, not a narrative recap, so downstream skills can consume it directly. | Claude | Post-Condition bullet 2. | Each Post-Condition names a specific record, field, or state value and what it changed to. | TBD, pending user input | Post-Condition (checkable-state requirement) |
