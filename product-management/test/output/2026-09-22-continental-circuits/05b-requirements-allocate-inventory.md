# Functional Requirements: Allocate Chipset Inventory to a Production Run

| Requirement ID | Requirement | Component | Detail | Acceptance Criteria | Priority | Source |
| --- | --- | --- | --- | --- | --- | --- |
| REQ-AllocateChips-01 | Continental ERP shall calculate the required quantity of each bill-of-materials chip for a scheduled production run. | Continental ERP | Basic Path step 2. | Every chip in the Trustpoint Hub's bill of materials has a calculated required quantity for the run before the inventory check runs. | TBD, pending user input | Basic Path #2 |
| REQ-AllocateChips-02 | Continental ERP shall check on-hand and incoming inventory against approved-vendor-list suppliers for each required chip. | Continental ERP | Basic Path step 3. | Every required chip has an on-hand-plus-incoming total, computed only from approved-vendor-list suppliers, before reservation runs. | TBD, pending user input | Basic Path #3 |
| REQ-AllocateChips-03 | Continental ERP shall reserve the required quantity of each chip against a run when sufficient inventory is available. | Continental ERP | Basic Path step 4. | Each required chip with sufficient inventory shows a reservation record tied to the run's ID. | TBD, pending user input | Basic Path #4 |
| REQ-AllocateChips-04 | Continental ERP shall notify the Sourcing Manager of the confirmed allocation for chips flagged as supply-constrained. | Continental ERP | Basic Path step 5. | The Sourcing Manager receives a notification listing every supply-constrained chip reserved for the run and the quantity. | TBD, pending user input | Basic Path #5 |
| REQ-AllocateChips-05 | Continental ERP shall add a released, fully allocated run to the Assembly Line's work queue. | Continental ERP | Basic Path step 7, Post-Condition (Basic Path exit). | The Assembly Line's work queue includes the run immediately after the Production Planner releases it. | TBD, pending user input | Basic Path #7, Post-Condition (Basic Path exit) |
| REQ-AllocateChips-06 | Assembly Line shall consume only reserved chip inventory when building units for a run. | Assembly Line | Basic Path step 8. | Units built for a run draw exclusively from that run's reserved-inventory records, never from unreserved or another run's reserved stock. | TBD, pending user input | Basic Path #8 |
| REQ-AllocateChips-07 | Continental ERP shall break a tie between approved suppliers with sufficient stock for the same chip by reserving from the supplier with the nearer lot expiration. | Continental ERP | Alternate Path A. | When two or more approved suppliers can each fully cover a chip's required quantity, the reservation comes from whichever supplier's lot expires soonest. | TBD, pending user input | Alternate Path A |
| REQ-AllocateChips-08 | Continental ERP shall flag a run as partially allocated when on-hand plus incoming inventory can't cover a required chip. | Continental ERP | Exception Path A, step 4 (flagging). | A run with an uncovered required chip shows a partially-allocated status rather than a forced full allocation. | TBD, pending user input | Exception Path A |
| REQ-AllocateChips-09 | Continental ERP shall notify the Sourcing Manager of the specific chip and shortfall quantity when a run is flagged partially allocated. | Continental ERP | Exception Path A, step 4 (notification). | The Sourcing Manager receives a notification naming the specific chip and the exact shortfall quantity for the run. | TBD, pending user input | Exception Path A |
| REQ-AllocateChips-10 | Continental ERP shall re-check inventory against a shortfall chip once the Sourcing Manager reports a resolved quantity and availability date. | Continental ERP | Exception Path A, step 6, rejoin to Basic Path #3. | The inventory check re-runs for the specific shortfall chip using the Sourcing Manager's reported quantity and date, without re-checking chips that weren't short. | TBD, pending user input | Exception Path A |
| REQ-AllocateChips-11 | Continental ERP shall replace an unresolved-shortfall run's quantity and/or start date with the Production Planner's revision, and drop the reserved-inventory record for the uncovered chip. | Continental ERP | Exception Path B, step 5, Post-Condition (Exception Path B exit). | The run record shows the revised quantity, revised start date, or both; no reserved-inventory record exists for the chip that couldn't be covered. | TBD, pending user input | Exception Path B, Post-Condition (Exception Path B exit) |

## Gaps flagged, not invented

- The use case's Open Issues/Notes flags that whether chip inventory is lot-tracked with expiration data across every component category (not just secure elements) isn't confirmed. REQ-AllocateChips-07 depends on it; no requirement above assumes lot-tracking exists for a category the use case didn't confirm it for.
- Whether Continental ERP holds or releases a partial reservation while Sourcing works an Exception Path A shortage isn't specified. REQ-AllocateChips-10 doesn't assume either behavior; it only requires the re-check to happen once Sourcing reports a resolution.
