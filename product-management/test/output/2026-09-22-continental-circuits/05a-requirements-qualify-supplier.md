# Functional Requirements: Qualify a New Chipset Supplier

| Requirement ID | Requirement | Component | Detail | Acceptance Criteria | Priority | Source |
| --- | --- | --- | --- | --- | --- | --- |
| REQ-QualifySupplier-01 | Continental ERP shall create a qualification case when a Sourcing Manager submits a qualification request. | Continental ERP | Basic Path step 2 (case creation). | A qualification case record exists, naming the candidate supplier and component category, immediately after a Sourcing Manager submits a request. | TBD, pending user input | Basic Path #2 |
| REQ-QualifySupplier-02 | Continental ERP shall request fab-location, export-control classification, and capacity documentation from the Candidate Supplier when a qualification case is created. | Continental ERP | Basic Path step 2 (documentation request). | The Candidate Supplier receives a documentation request naming all three required items within [DOCUMENTATION_DEADLINE] of case creation. | TBD, pending user input | Basic Path #2 |
| REQ-QualifySupplier-03 | Continental ERP shall add an approved supplier's part number(s) to the approved-vendor list for the applicable component category, selectable in production-run allocation, when the Compliance Officer approves a qualification case. | Continental ERP | Basic Path steps 5-6. | The approved-vendor list contains a new entry linking the supplier and its part number(s) to the component category, and the supplier is selectable in production-run allocation. | TBD, pending user input | Basic Path #5-6, Post-Condition (Basic Path exit) |
| REQ-QualifySupplier-04 | Continental ERP shall request only the specific missing documentation items from the Candidate Supplier when a submission is incomplete. | Continental ERP | Alternate Path A. | The Candidate Supplier receives a request naming only the items the Compliance Officer found missing, not a repeat of the full original request. | TBD, pending user input | Alternate Path A |
| REQ-QualifySupplier-05 | Continental ERP shall record the specific sourcing-policy reason when the Compliance Officer rejects a candidate supplier. | Continental ERP | Exception Path A, step 5. | The qualification case is recorded as rejected with a policy reason naming the specific failure (non-U.S./EU fab, or FCC Covered List match). | TBD, pending user input | Exception Path A |
| REQ-QualifySupplier-06 | Continental ERP shall notify the Sourcing Manager of a candidate supplier's rejection and the reason. | Continental ERP | Exception Path A, step 6. | The Sourcing Manager receives a notification naming the rejected candidate and the specific policy reason. | TBD, pending user input | Exception Path A |
| REQ-QualifySupplier-07 | Continental ERP shall mark a qualification case as stalled when the Candidate Supplier does not submit documentation within [DOCUMENTATION_DEADLINE]. | Continental ERP | Exception Path B, step 3. | A qualification case with no documentation submission after [DOCUMENTATION_DEADLINE] shows a stalled status. | TBD, pending user input | Exception Path B |
| REQ-QualifySupplier-08 | Continental ERP shall notify the Sourcing Manager when a qualification case is marked stalled. | Continental ERP | Exception Path B, step 4. | The Sourcing Manager receives a notification naming the stalled case and candidate supplier. | TBD, pending user input | Exception Path B |

## Gaps flagged, not invented

- `[DOCUMENTATION_DEADLINE]`: the use case's Open Issues/Notes flags that this deadline isn't specified. REQ-QualifySupplier-02 and REQ-QualifySupplier-07 both depend on it; no requirement above invents a value.
- Whether a rejected candidate can be resubmitted after correcting the failure (e.g., relocating its fab) isn't specified in the use case. No requirement above assumes an answer either way.
