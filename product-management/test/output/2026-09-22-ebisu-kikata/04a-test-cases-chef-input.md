# Test Cases: Chef Input (Commissioning)

| Test Case ID | Title | Covers | Preconditions | Steps | Expected Result |
| --- | --- | --- | --- | --- | --- |
| TC-ChefInput-01 | Successful commissioning scan | Basic Path | Menu items loaded; RFID reader operational; each plate has a unique RFID tag; Chef Interface running and scanning the workspace. | 1. Chef prepares the menu item and places it on plates. 2. Chef places plates in the workspace. 3. Chef touches the menu item on the Chef Interface. 4. Chef reviews the displayed plate count and menu description. 5. Chef confirms the scan. | Live Inventory contains a new record associating the RFID UIDs with the menu item and a "born on" timestamp. |
| TC-ChefInput-02 | No RFID tags detected in workspace | Exception Path A | Same as TC-ChefInput-01, except no tagged plates are in the workspace (or antennas are misconfigured) when the chef touches the menu item. | 1. Chef touches the menu item on the Chef Interface with no plates in the workspace. 2. Kaiten IQ reports it sees no RFID tags and asks the chef to take corrective action. 3. Chef acknowledges the message. | No Live Inventory record is created; the use case re-enters at Basic Path #1 with Kaiten IQ again presenting the menu item list. |
| TC-ChefInput-03 | Chef rejects the scan | Exception Path B | Same as TC-ChefInput-01, through Kaiten IQ displaying the scanned plate count and menu description. | 1. Chef reviews the displayed plate count and finds it doesn't match the actual plates. 2. Chef indicates an error in the scan. 3. Kaiten IQ suggests corrective actions. 4. Chef acknowledges and adjusts the plates in the workspace. 5. Chef re-touches the menu item to re-scan. | No Live Inventory record is created from the rejected scan; the use case re-enters at Basic Path #4 for the chef to re-scan. |
